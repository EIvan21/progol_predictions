# v0.4.0 — Interactive Telegram bot + arbitrary upcoming-match predictions

Released against `progol-trainer` model run on 2026-05-06 (concurso 2332).

## Highlights

- **Interactive Telegram bot** on a dedicated e2-micro VM (`progol-bot`),
  long-polling 24/7 independent of the weekly trainer run.
- **`/predecir_partido EQUIPO_A vs EQUIPO_B`** now answers for any team
  pair playing in the next 7 days — not just the active Progol slate.
- **DB-backed bot auth** with role/status workflow; new users register as
  `pending` via `/start`, owner approves from chat with `/aprobar`.

## New features

### Bot Phase 1 (`src/progol/bot/app.py`)
- Long-polling app via `python-telegram-bot 20.7`.
- Public commands: `/start`, `/whoami`.
- User commands (auth required): `/help`, `/ultima_prediccion_progol`,
  `/predecir_progol`, `/predecir_partido`.
- Admin commands (owner/admin role): `/usuarios`, `/aprobar`, `/bloquear`.
- Per-message audit trail in `bot_messages`; conversation state
  persistence in `bot_threads` (used by Phase 2 budget flow).
- Dedicated `data/bot.db` — separate from trainer's `progol.db` so
  `gsutil rsync` can't wipe auth state.
- `manage_users` CLI for the initial owner seed via SSH.

### Pre-computed upcoming-match predictions
- New `match_predictions` table (rolling 7-day window).
- `predict_upcoming_fixtures()` runs at the end of the weekly Progol path,
  scoring all `matches` rows where `status != 'FT'` and kickoff within
  7 days. Skips bookmaker odds (would be N extra API calls); uses the
  same model + temperature as the Progol slate.
- `cleanup_old_match_predictions` purges past kickoffs each run so the
  table stays bounded.
- `database.resolve_team_id_by_name` (fuzzy team-name → `team_id`) +
  `get_upcoming_match_prediction` power the bot's fallback layer.
- Bot's `/predecir_partido` is now layered: try active concurso first,
  fall back to upcoming fixture lookup.

### Autonomous Telegram notifications
- `infra/startup.sh` POSTs the Wednesday slate to the user's Telegram
  chat after `predict` (non-fatal, gated on `TELEGRAM_BOT_TOKEN` +
  `TELEGRAM_CHAT_ID`).
- Notification reuses the same `format_concurso_message` formatter as
  the interactive bot, so manual and autonomous outputs match.

### Historical concurso backfill
- `backfill_fixture_ids.py` joins scraped historical games to the
  `matches` table via fuzzy team names + ±10-day window; settles
  `actual_label` automatically.
- `backfill_concurso_predictions.py` joins
  `progol_concurso_games.fixture_id` to `predictions.db` to copy
  predicted_label/probs across when a historical fixture happened to be
  scored in some prior live run.

## Improvements

- `database.py`: 6 new helpers (`bot_*`, `upsert_match_prediction`,
  `resolve_team_id_by_name`); pandas is lazy-imported so the slim bot
  VM doesn't need it.
- `requirements_bot.txt` — slim install (`telegram + dotenv + thefuzz +
  bs4 + requests`) for the e2-micro VM. Full ML stack stays on the
  trainer.
- Bot output uses real Markdown (bold/italic) instead of fixed-width
  code blocks that render cramped on mobile.

## Bug fixes

- `_decode_probs` now accepts both `{"L":..,"E":..,"V":..}` dicts and
  `[L,E,V]` lists (the trainer writes the dict shape; the formatter
  was silently dropping every game to "sin predicción").
- `progol-trainer` startup script no longer masks slate-scraper failures
  with `|| echo`; predict step bails cleanly if scrape returns < 21
  matches.
- `predictions/` directory is now rsync'd to GCS in the trainer's
  `finalize` trap, not just `slate-*.json`.

## Infrastructure

- New VM `progol-bot` (e2-micro, free tier, us-central1-a).
- `progol-bot.service` systemd unit, idempotent `bot_startup.sh`.
- Reuses `progol-runner` service account for GCS access.
- Boot disk: 10GB pd-standard.

## Known limitations

- `match_predictions` only refreshes on Wednesday's trainer run; the
  bot won't pick up odds shifts intra-week.
- Predictions are model-only for the upcoming-fixtures path (no
  bookmaker blend), in contrast to the Progol slate which keeps the
  full blend.
- 562 of 568 historical concursos in `quinielaposible.com` have their
  slate as an embedded image (not HTML); deferred to a future OCR pass.
