## Recent decisions (and why)

1. **Lower fuzzy threshold 75 → 70 with `[LOW-CONFIDENCE]` warnings.** Several real matches (CELTIC vs HEARTS = 72) were failing on the strict side. Adding a warning band (70–74) catches them while making the marginal calls auditable in the log.
2. **Widen `days_forward` 5 → 8 → 12.** Progol slates can span ~2 weeks; the 5-day window missed cup finals and late-scheduled friendlies. 12 days covers through the Sunday+Monday after the Wednesday run.
3. **`NICKNAME_MAP` is structural, not cosmetic.** Each new fixture type (J-League, Concachampions, women's, national teams in Spanish) requires entries OR the resolver returns FAILED → `predict.py` writes a partial concurso. We're now treating "21/21 resolved" as the gate. Plan still calls for a healthcheck that alerts when this drops below 21.
4. **Re-ran the trainer manually mid-week to validate fixes.** Confirmed: 10/21 (pre-fix) → 20/21 (commit `ecfd28f`) → 21/21 (commit `0b2f0ad` adding CONCACAF Champions Cup league 16 for TOLUCA vs TIGRES final).
5. **Kept STANDARD provisioning on `progol-trainer`** (vs Spot). Earlier Spot preemption truncated a run silently; the cost differential isn't worth the risk on a once-a-week ~35-min job.

## Things you asked me to remember

- **Don't mock the DB in tests of `progol_history`** — the fixture (`concurso_db`) uses tmp_path + monkeypatch on `DB_PATH` so each test seeds its own rows. Don't refactor to mocks; the integration coverage is the point.
- **Telegram message dash character matters.** CLI uses ASCII `-` (Windows cp1252 can't render em-dash), HTML bot output uses `—`. The `_fmt_score(bucket, dash='-')` helper parameterizes this; preserve it.
- **`compared` vs `settled` denominator** in `get_concurso_hits` — `compared` requires both labels present, `settled` requires only actual. Don't conflate when adding new diagnostics.
